# Orca Preset Assistant 使用说明

## 第一次使用

1. 在 Orca 主窗口打开 **Preset Assistant** 页面。
2. 点击“选择或创建工作区”，选择一个用于长期保存预设和打印档案的普通父文件夹；不要选择 `UserPresets` 本身。
3. Orca 会保存这个位置。第一次启用或更换工作区后，按提示重启一次 Orca。
4. 重启后点击面板右上角刷新按钮；看到刷新时间或成功提示即表示面板已重新读取。

工作区内只会出现：

```text
UserPresets\
  machine\
  process\
  filament\
  AGENTS.md
PrintHistory\
```

这些目录由软件自动创建。`AGENTS.md` 保存 Codex 的提案、写入和验证规则；如果工作区已经有这个文件，软件不会覆盖。

## LAN Only 打印

定制 Orca 没有 Bambu Lab 的应用签名，因此较新打印机固件的普通授权模式可能拒绝发送打印，并返回 `-26`。只使用 LAN Only 时，按下面配置：

1. 在打印机屏幕打开 LAN Only 设置；
2. 开启 LAN Only；
3. 在同一处手动开启 **Developer Mode**；
4. 回到 Orca，重新连接打印机，然后重新发送。

这条路线不需要 Bambu Connect。Developer Mode 会开放 MQTT、实时画面和 FTP 等局域网接口，只在可信局域网中使用。该开关只能由你在打印机屏幕上操作，助手只负责解释错误，不会远程改变打印机安全设置。

如果仍然失败：

- 确认错误是否仍为 `-26`；
- 确认 Developer Mode 没有在固件更新或设置变更后被关闭；
- 在 Orca 中断开并重新连接设备；
- 重启 Orca 后再试一次。

官方背景说明见 [Bambu Lab：Updates and Third-Party Integration with Bambu Connect](https://blog.bambulab.com/updates-and-third-party-integration-with-bambu-connect/)。

## User Presets

- 顶部数字显示三类用户预设数量。
- 搜索框可以按名称、父预设或设置 ID 查找。
- 点击一条预设，在右侧查看身份、父预设、验证问题和最近打印结果。
- 每条预设会显示本地版本状态；“只看有变化”可以过滤出新增、已修改或仅元数据变化的预设。
- machine 预设可以查看和归档，但 Codex 不会自动修改机器级参数。

### 本地版本与恢复

若 `UserPresets` 还不是一个独立 Git 仓库，面板会显示“启用本地版本”。确认后只会在
`<Workspace>\UserPresets` 初始化本地仓库，不连接 GitHub。

- “保存版本”只保存 `machine`、`process`、`filament`；
- “查看变化”显示当前未保存差异；
- “版本历史”列出本地快照；
- “恢复”会先检查未保存变化，再把三个预设目录恢复到所选版本并创建一个新的恢复快照；
- `PrintHistory`、`AGENTS.md`、`CHANGELOG.md` 和其他文件不属于面板版本范围。

需要 GitHub 同步、分支或更复杂的 Git 操作时，把 `<Workspace>\UserPresets` 作为 Codex
任务文件夹打开并明确提出要求。

## 让 Codex 给建议

第一次使用 Codex 插件时，点击标题栏的 `?` 可以看到安装命令、权限说明和示例提问。
完整安装步骤见 [Codex 插件说明](./CODEX_PLUGIN.md)。

在设置中选择数据范围：

- **通用建议**：Codex 不读取 Orca，只按你的文字描述回答；
- **当前设置**：可读取当前机器、工艺、材料和实际有效参数，不读取模型；
- **当前项目**：本次 Codex 会话可读取当前预设、完整参数、零件摆放，并检查当前项目内 STL/3MF 的几何形状；
- **项目外模型文件**：只有需要分析未载入当前项目的 STL/3MF 时，才使用单文件授权。

刷新面板不会自动扩大数据权限。只有你明确说“读取当前设置”或提出必须依赖当前项目的请求时，Codex 才读取 Orca 实时状态。

## 修改永久用户预设

更新或新建 process / filament 用户预设时，Orca 可以开着，也可以关闭：

1. Codex 读取目标预设；新建时通常读取你指定的现有用户预设作为来源。
2. Codex 先记录目标文件、修改前后数值、删除项和理由，再直接修改工作区里的 JSON 与匹配 `.info`。
3. 助手在后台保存具体差异和“已记录 / 已写入 / Orca 已加载 / 冲突”状态；这些记录不占用切片面板，也不要求接受或拒绝。
4. 点击面板右上角刷新。若 Orca 开着，它只热加载这次记录的新增或修改预设，并用内存中的实际值确认；若 Orca 关闭，文件已经有效，下次启动后再刷新确认加载。

官方预设和 machine 预设不能直接覆盖。新预设的文件名、JSON 名称、设置 ID、父预设和 `.info` 必须一致；从现有预设复制时不会继承原预设的云同步身份。

如果要刷新的正是 Orca 当前选中预设，而且 Orca 内还有未保存编辑，系统不会静默覆盖；后台状态会保持“已写入，待 Orca 加载”，而不会错误记录为“Orca 已加载”。先在 Orca 中处理未保存编辑，再刷新即可。

## 修改当前项目

只有你明确要求“仅改当前项目”时才走提案流程。Codex 会先读取当前设置和 Orca 发布的 `writeCapabilities`，面板显示修改前、修改后与理由，由你确认后写入当前项目。隐藏参数会明确标记为当前版本没有可见面板控件；只有原生回执和新 revision 回读都匹配时才算应用成功。

当前项目修改成功后可以回滚最近一次修改。若之后已经手工改过参数、切换过状态或回滚凭证失效，系统会拒绝自动回滚，避免覆盖后续工作。

## Print History

开启“提交打印后自动建档”后，Orca 成功提交打印时会自动创建一条 pending 记录，保存当时
完整有效参数。失败提交和仅上传不会建档。

3MF 策略：

- **始终**：自动导出当前项目副本；
- **每次询问**：提交打印后询问是否同时保存项目；
- **从不**：只保存设置，不保存项目。

打印结束后进入 Print History，把结果改为成功、问题或失败，并补写备注。修改结果不会改写
当时的 `settings.json`。

也可以点击“记录打印”手动选择工艺、材料、结果和可选 3MF 建档。手动档案在没有 Orca
权威有效设置时只保存所选用户预设快照，界面会标明其快照质量。

点击任意记录会打开右侧详情。自动建档记录可以展开查看全部有效参数；“在资源管理器中打开”
会定位到包含 `record.json`、`settings.json` 和可选 `project.3mf` 的历史包。删除记录时，
整个历史包会移入 Windows 回收站，原始项目和 Orca 预设不会被删除。

## 数据位置与备份

自定义预设都在 `<Workspace>\UserPresets`；每次打印档案都在
`<Workspace>\PrintHistory\<run-id>`。直接备份整个工作区即可保留两类数据。

卸载或更新应用不会主动删除这个工作区。
