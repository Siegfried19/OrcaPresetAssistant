# Orca Preset Assistant v0.6.4

这一版完成了工作区用户预设与 Orca 当前进程之间的双向热同步，并把桌面入口改成始终选择最新已验证完整构建。

## 主要变化

- Codex 修改永久 process / filament 用户预设时，先在后台记录精确差异和文件哈希，再直接修改工作区 JSON；不增加需要二次批准的切片面板卡片。
- 刷新会在当前 Orca 进程中加载新增或修改的用户预设，并用原生回读和新 revision 验证实际值。
- 删除工作区预设的 JSON 或 `.info` 后，再次刷新会把它从 Orca 内存列表安全卸载，不需要重启。
- 热卸载只处理工作区直属用户预设；官方、默认、项目内嵌、工作区外、仍被子预设继承或带未保存编辑的选中预设均受保护。
- 桌面快捷方式通过动态启动脚本验证构建清单、原生 DLL 和 helper 哈希后选择最新完整版本。
- 修复提案摘要与右侧详情之间的选择关联，避免提案目标不在当前过滤结果中时无法打开详情。
- 审批升级前遗留提案时保留其原始写入目标和另存名称，避免被当前界面的默认值覆盖。
- 超过 32 条待同步文件记录时自动按原生接口上限分批刷新，避免整批热同步失败。
- Codex 插件增加永久文件修改日志、严格 `.info`/继承校验与热加载回执流程。

## 已验证

- TypeScript、ESLint、Prettier、Vitest 和 Codex 插件 MCP 测试通过。
- Orca 原生 Preset Assistant 与 Workspace/HotReload 定向测试通过，Windows Release 构建成功。
- `0015-hot-reload-workspace-user-presets.patch` 可从干净 Orca 产品基线按补丁链重放。
- 实机在同一个 Orca 进程中验证：创建临时工艺并刷新后立即出现；删除对应 JSON 和 `.info`、再次刷新后立即消失。

## 已知限制

- 当前仍是未签名的 Windows 早期预览版，Windows 可能显示未知发布者警告。
- machine 参数保持只读；设备连接、运动安全、脚本、路径和官方系统预设不会由助手任意改写。
- 安全保护拒绝卸载带未保存编辑的当前预设或仍被其他用户预设继承的预设；处理冲突后可再次刷新。
- 上游 Orca 升级后仍需重放原生补丁并完成回归测试。
